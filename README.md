# 工作树 · DSH Worktree Desk

在 DeepSeek Harness 侧栏打开 **工作树**，一眼看到本机所有仓库的工作树：哪些有改动、哪些没推送、哪些目录已经没了，就地看差异、分支，以及能匹配到的 Codex / ZCode / DSH 会话。

面板只读取仓库状态，不创建、移动、切换、合并工作树，也不删文件。只有两件事会写东西，都由用户主动点击触发：

- **在 DSH 新开会话**：把这个目录登记为 DSH 工作区（幂等），然后进入新会话。
- **清理失效登记**：唯一的 Git 写操作，执行 `git worktree prune`，先预览、确认后才执行。

## 安装

环境：DeepSeek Harness（DSH）桌面端 `0.2.2-rc.5` 起、低于 `0.3.0`；需要 Git。没有运行时依赖，`dist/client.js` 随包带上，不用先装开发依赖。只在 macOS 上验证过；其它系统未验证，「在应用中打开」「跳到 Codex」这类系统联动也只在 macOS 可用。

安装会改动 DSH 桌面端的 profile，所以顺序是：**完全退出 DSH → 安装 → 重新打开**。`desktop` 这个 profile 要在桌面端打开过至少一次之后才存在。

### 自己装

先完全退出 DSH 桌面端（⌘Q），再执行：

```bash
DSH="/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh"
"$DSH" plugin --profile desktop add "https://github.com/Thomas-zz/dsh-worktree-desk.git#v0.4.0"
```

然后重新打开 DSH，左侧栏会多一个「工作树」。`dsh plugin add` 底层是 pnpm，所以也接受本地目录：

1. 从 [Releases](https://github.com/Thomas-zz/dsh-worktree-desk/releases) 下载 `dsh-worktree-desk-X.Y.Z.tgz` 和 `SHA256SUMS`，放在同一目录，运行 `shasum -a 256 -c SHA256SUMS`。
2. 解压到一个会长期保留的目录：`tar -xzf dsh-worktree-desk-X.Y.Z.tgz -C <目录> --strip-components=1`。
3. `"$DSH" plugin --profile desktop add <目录>`。克隆仓库后 add 仓库目录也可以。还可以在桌面端「设置 → 插件」里从本地目录安装。

**升级**：完全退出 DSH，把命令里的标签换成新版本重跑（本地目录方式则是更新目录内容），再重新打开。
**卸载**：完全退出 DSH 后运行 `"$DSH" plugin --profile desktop remove dsh-worktree-desk`，或在「设置 → 插件」里移除。

## 怎么用

**总览**

- 打开就是全部仓库的工作树，默认按「需要关注」排序：冲突、合并/变基进行中、读取失败、有改动、有未推送、落后上游、干净、登记失效。可切成「最近改动」。
- 只有主检出、没有改动、也没有会话的仓库默认收进「其余 N 个仓库」，不占位置。
- 面板够宽时左侧有仓库栏，顺序与计数同总览；选中一个仓库就进入它的「工作树 / 本地分支」两个页签。

**一行工作树**

- 第一行是分支名（分离 HEAD 显示提交短号）和「主目录」标记；第二行依次是工单号、状态、与上游的领先/落后、最近改动时间、关联工具。
- 工单号从分支名里提取（如 `7001`、`DEMO-10431`），同一工单同一种颜色，点它就只看这个工单的工作树。
- 关联工具显示为首字母（C = Codex，Z = ZCode，D = DSH）；最近 30 分钟有活动或正在运行时高亮。
- 点行看详情。行尾的按钮直接「在 DSH 新开会话」；「⋯」和右键菜单里有更多操作。

**筛选与搜索**

- 状态标签：全部、有改动、有未推送、落后上游、异常、失效登记；右侧可按关联工具筛选。
- 搜索框匹配仓库、分支、工单号或路径，多个关键词用空格分隔（同时满足）。
- 快捷键：`/` 或 `⌘F` 聚焦搜索，`↑` `↓` 移动，`Enter` 打开，`Esc` 返回或清除。

**详情**

- 顶部是路径、最近一次提交、上游对比。操作栏：「在 DSH 新开会话」（已有 DSH 会话时主按钮是「打开 DSH 会话」）、在本机应用里打开（终端、编辑器、Git 客户端、访达，取自宿主的「在应用中打开」列表）、复制路径或分支名。
- 「文件改动」：文件按目录归并，带增删行数，可按未暂存/已暂存/未跟踪筛选。改动不超过 40 个文件时目录默认展开，更多时先收起，可一键全部展开；筛选或搜索时目录自动跟着展开。点文件就地展开差异：行号、词级高亮、切换暂存区或工作目录这一层。面板够宽时可切成左右并排（切过去会自动打开换行），长行可手动切换是否换行。
- 「关联会话」：未归档的 DSH 会话可在宿主打开；macOS 可按 ID 打开本机 Codex。ZCode Desktop 3.18.2 没有按本地任务 ID 打开原会话的桌面入口，按钮会复制标题并打开任务登记的 ZCode 工作区，仍需手动查找。
- 「在 DSH 右栏看完整差异」是显式入口：需要有同一物理工作树的 DSH 会话，插件会切到那个会话，在宿主原生右栏打开「本地变更」并定位到文件。原生页保留 DSH 的比较基线、文件筛选和审阅设置，它和清单的「未提交」不是同一个范围，文件数可以不同。

**本地分支**

- 分组头右侧的「分支 N」进入。可按全部、未检出、有未推送、已并入筛选；每行显示上游对比、提交短号、时间和标题。
- 「查看工作树」跳回对应的那一行。**未检出不等于可以删除。**

**失效登记**

- 目录已经不存在的工作树登记单独折叠成一行「N 棵登记已失效」，展开后可清理。
- 清理先预览：列出将被移除的登记（`git worktree prune --dry-run`），确认后才执行。期间登记发生变化会要求重新确认；已锁定的登记不动；不删除任何文件。目录之后如果恢复，需要重新登记为工作树。

**怎么读这些数字**

- 工作树的「最近改动」取 HEAD 提交时间和所有 Git 改动文件（含未跟踪）的修改时间中较晚的一个；删除文件用最近仍存在的父目录时间估算；取不到时间的排在最后。不用聊天时间或扫描时间代替文件变化时间。
- 上游比较只针对本地已有的跟踪引用，不执行 `fetch`：「已同步」不代表刚刚检查过远端；「未设上游」不等于没有推送。
- 「起点」只陈述本地分支引用日志里实际记下的内容，不推测父分支；「上游」是当前分支配置的默认比较对象，两者可以不同。
- 工具、仓库旁的数字是匹配到的工作树数，包含主检出。同一工具的多个会话只计一棵，同一棵树可同时计入多个工具。这是目录关联，不是在线占用统计。
- 目录和会话来自同一次发现快照；文件状态在打开面板时逐仓库读取（读完一个显示一个），详情缓存 15 秒。点「刷新」重新读取，不在后台轮询。

## 项目来源和目录匹配

默认从 DSH 工作区、Codex 桌面项目/聊天索引和 ZCode 本机项目/任务索引发现仓库。项目根本身不是 checkout 时，还查找它的直接子目录；不递归扫描整个 home 或磁盘。对同仓不同 checkout 按真实 Git common directory 去重，不按仓库名或远程地址合并。然后以 `git worktree list --porcelain -z` 为准，从仓库发现其它登记的工作树，包括临时目录和不同工具创建的目录。

没有被以上工具记录的仓库，可以在对应 DSH profile 的 `cordis.patch.yml` 中补充目录。多个条目使用同一个 `name` 即可组合成同一业务项目。这是可选的插件配置，不写入业务仓库。

```yaml
- id: worktree-desk
  config:
    projects:
      - name: 我的项目
        root: /absolute/path/to/frontend
      - name: 我的项目
        root: /absolute/path/to/backend
```

| 来源 | 关联依据 | 边界 |
|---|---|---|
| Codex | 本机 `state_*.sqlite` 的聊天 cwd；桌面项目索引可选 | 不把 `codex/` 分支名或目录名当作所有权，也不把更新时间当在线状态；子代理与守护审查线程不计入 |
| ZCode | 本机任务的工作树目录、执行目录，缺失时退回任务工作区 | 证据类型标在会话行；不把项目空间等同于实际占用 |
| DSH | 当前宿主会话摘要的工作目录投影，缺失时显示为初始目录关联 | 仅宿主报告运行且能定位工作目录时才标运行中 |

匹配取会话目录所在的最近 checkout，不把父项目下所有会话分配给每一棵树。只展示当前可关联的记录；历史记录、空白结果和索引不可用都不是工作树空闲的证明。SSH、容器及其它机器上的仓库不在范围内。

## 边界与降级

- 读取类接口（清单、仓库详情、单文件差异、原生会话匹配、清理预览）是 DSH owner 认证的 GET 路由。插件只接受清单里的 ID，不接受任意路径、Git 参数或 URL。
- 会产生动作的接口都是独立的 POST 路由，并要求对应的 `X-Worktree-Action` 请求头：新开/打开会话、在系统应用中打开、清理失效登记。清理还带上确认时看到的条数，对不上就拒绝。
- 原生差异只在点击时重新核验工作树登记和 DSH 会话当前工作目录，不会仅因同仓、分支同名或会话初始目录相同就打开。
- 无插件数据库、遥测或聊天正文查询。Codex/ZCode 索引通过 SQLite 只读连接访问。
- Git 用参数数组调用，关闭可选的索引刷新写入、hooks、fsmonitor 和隐式网络获取。已跟踪文件依赖外部 clean/process 过滤器时跳过文件状态而不执行它，仍保留分支与目录信息。超时、过大的命令输出、丢失或不可读的目录都不会显示为「干净」。
- 单文件差异最多 1 MiB 或 4000 行，超出会截断并提示到 DSH 右栏看完整差异；未跟踪的新文件只读前 128 KiB 的原文，二进制和符号链接不读；文件清单最多列前 100 项。

## 开发

```bash
npm ci
npm run build      # 打包 client/ → dist/client.js
npm test           # 纯函数与 Git 解析，含在临时仓库里真实执行一次清理
npm run dev:web    # 起一个隔离的 Web 宿主来手测（独立 profile，不挂桌面凭据）
```

`src/` 是宿主侧（来源适配、Git 读取、聚合与路由），`client/` 是独立侧栏面板，React 由 DSH 宿主提供。

**发布**：公开仓一个版本一个提交。把开发目录的内容（不含 `node_modules`）同步进公开仓的克隆，用版本号作提交信息提交、打同名注释标签；Release 附上 `npm pack` 的包和 `SHA256SUMS`。提交身份用 GitHub noreply 邮箱，仓库里不放个人路径和内部名称。

## 已验证的范围（2026-11-25）

- 隔离 DSH Web profile + 真实本机仓库与 Codex/ZCode 只读快照。浅色与深色主题，1920 / 1440 / 1000 / 560 / 390 五种宽度：清单与详情并排、窄屏堆叠（清单 → 详情 → 整页差异 → 返回）均无横向溢出、无控制台报错。
- 走过的动线：渐进加载、状态/工具筛选、搜索、工单色标、分支视图与筛选、分支跳回工作树、右键菜单与「⋯」菜单、就地差异（上下对照、左右并排、粘性标题）、会话页、帮助、清理确认（真实仓库上只预览和取消）。
- 隔离宿主内从面板「在 DSH 新开会话」进入该目录的新会话。
- 清理失效登记在临时仓库里真实执行：预览 → 执行 → 登记消失，锁定与在用的不动（`npm test`，26 条）。
- 安装：在干净的隔离 profile 里分别从 git 地址（带标签）和 Release 包解压目录安装，再把装出来的 profile 真实启动，面板正常加载；并在模拟的 desktop profile 上（全新、以及之前用本地目录装过）用安装 prompt 里的原命令匿名安装通过。
- 本轮修掉的问题：清理预览一直为空（Git 把预检报告写到 stderr，封装只读了 stdout）；1920 以上宽度行内工具标签被挤压、按钮掉行；左右并排时右栏跑出屏幕；说明对话框按 Esc 关不掉；改动较多时文件全藏在折叠目录里。
- 没验证的：真实桌面宿主上的本轮版本没有做专门回归（上面的回归都在隔离宿主里做，跑的是同一个宿主程序）。

此前版本：0.2.0、0.3.0 在维护者的真实桌面仓库上验证过逐行差异、Codex 导航，以及从文件行进入宿主原生「本地变更」。临时仓库覆盖过暂存且又修改同一文件、重命名、未跟踪、冲突和合并中、已锁定、目录移走、未产生首个提交、裸仓库和外部过滤器降级，读取前后样例 Git 索引 mtime 不变；未认证请求返回 401，未知仓库 ID 和 POST 请求不能读取数据。
