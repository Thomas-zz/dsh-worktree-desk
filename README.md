# 工作树 · DSH Worktree Desk

在 DeepSeek Harness 侧栏打开 **工作树**，一眼看到本机所有仓库的工作树：哪些有改动、哪些没推送、哪些目录已经没了；就地看差异和本地分支，发起 AI 代码审查并把结论标在对应的行上，以及能匹配到的 Codex / ZCode / DSH 会话。

面板本身只读：读取仓库状态，不创建、移动、切换、合并工作树，也不删文件。会动手的只有下面几件，都由你主动点击触发：

- **在 DSH 新开会话**：把这个目录登记为 DSH 工作区（幂等），然后进入新会话。
- **获取 / 拉取 / 推送**：获取直接执行；拉取和推送先告诉你将做什么（推到哪、几个提交、会不会在远端新建分支），确认后才执行。拉取只做快进，推送不强推。
- **AI 审查**：在这个目录新开一个 DSH 会话，发出一份只读审查的请求，再把结果标在差异上。
- **本仓库的审查提示词**：把你写的一段提示词存进这个仓库的 Git 公共目录（`.git/worktree-desk/review-prompt.md`）。
- **清理失效登记**：执行 `git worktree prune`，先预览、确认后才执行。

## 安装

环境：DeepSeek Harness（DSH）桌面端 `0.2.2-rc.5` 起、低于 `0.3.0`；需要 Git。没有运行时依赖，`dist/client.js` 随包带上，不用先装开发依赖。只在 macOS 上验证过；其它系统未验证，「在应用中打开」「跳到 Codex」这类系统联动也只在 macOS 可用。

安装会改动 DSH 桌面端的 profile，所以顺序是：**完全退出 DSH → 安装 → 重新打开**。`desktop` 这个 profile 要在桌面端打开过至少一次之后才存在。

### 自己装

先完全退出 DSH 桌面端（⌘Q），再执行：

```bash
DSH="/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh"
"$DSH" plugin --profile desktop add "https://github.com/Thomas-zz/dsh-worktree-desk.git#v0.5.0"
```

然后重新打开 DSH，左侧栏会多一个「工作树」。`dsh plugin add` 底层是 pnpm，所以也接受本地目录：

1. 从 [Releases](https://github.com/Thomas-zz/dsh-worktree-desk/releases) 下载 `dsh-worktree-desk-X.Y.Z.tgz` 和 `SHA256SUMS`，放在同一目录，运行 `shasum -a 256 -c SHA256SUMS`。
2. 解压到一个会长期保留的目录：`tar -xzf dsh-worktree-desk-X.Y.Z.tgz -C <目录> --strip-components=1`。
3. `"$DSH" plugin --profile desktop add <目录>`。克隆仓库后 add 仓库目录也可以。还可以在桌面端「设置 → 插件」里从本地目录安装。

**升级**：完全退出 DSH，把命令里的标签换成新版本重跑（本地目录方式则是更新目录内容），再重新打开。
**卸载**：完全退出 DSH 后运行 `"$DSH" plugin --profile desktop remove dsh-worktree-desk`，或在「设置 → 插件」里移除。

## 能做什么

**总览**

- 打开就是全部仓库的工作树，按仓库分组：带底色的一行是仓库，缩进排在下面的是它的工作树。默认按「需要关注」排序（冲突、合并或变基进行中、读取失败、有改动、有未推送、落后上游、干净、登记失效），可切成「最近改动」。只有主检出、没有改动也没有会话的仓库收进「其余 N 个仓库」。
- 面板够宽时左侧有仓库栏。选中一个仓库就只看它的：上面是它的工作树，清单末尾「本地分支」一段是它的全部分支。筛选条一直在，数字按当前范围算。
- 状态标签：全部、有改动、有未推送、落后上游、异常、审查过、失效登记；还能按关联工具（Codex / ZCode / DSH）筛选。搜索匹配仓库、分支、工单号或路径，多个关键词用空格分隔。
- 快捷键：`/` 或 `⌘F` 聚焦搜索，`↑` `↓` 移动，`Enter` 打开，`Esc` 返回或清除。
- 状态是打开或刷新那一刻读到的，不是实时的：再次打开先显示上次的结果（顶栏写明「读取于」什么时候），点刷新才重读；拉取、推送、获取、清理登记之后，相关的仓库会自动重读。

**一行工作树**

- 一棵工作树只占一行：分支名，行尾是要动手的数字——`↑` 未推送的提交数、`↓` 落后的提交数、`±` 改动的文件数；有冲突，或者合并、变基做到一半时是一个红色警示。
- 走过 AI 审查的树行尾有一个四角星，按结论着色（没有问题、有修改建议、有必须处理的问题），星后面是几处要处理；审查之后改动变了就变淡。标过「已审阅」的树行尾有进度环（`3/8`，都读完了是对勾）。
- 路径、上游、分支起点、最近一次提交、工单号和关联工具都在选中后的详情里。工单号从分支名里提取，同一工单同一种颜色，点它就只看这个工单的工作树。

**详情：就地看差异**

- 表头是分支名和要动手的事（「2 个提交未推送」「落后上游 N 个提交」）、路径、最近一次提交。操作栏一行三组：在这里开工（在 DSH 新开会话、AI 审查）、获取 / 拉取 / 推送、在本机应用里打开和更多。
- 文件改动分两个页签。**未提交**：工作目录和 HEAD 比的改动（已暂存、未暂存、未跟踪）。**未推送**：分支设了上游、又有没推送的提交时才有——和上游比，列出这些提交和改了的文件。正看着范围空了（提交完、推送完）而另一个范围还有东西，会自动换过去。
- 所有文件的差异从上到下铺开，滚动着看，不用逐个点开。文件树有**浮窗**、**固定**两种形态，用图钉切换：浮窗平时收成左缘的一条把手，鼠标停上去或点工具栏的「文件 N」才滑出来；固定时文件树占左边一栏、差异排在右边（文件区够宽才行）。文件树里可按状态或路径筛选，目录可折叠，能跳到上一个 / 下一个文件。
- 差异带行号和词级高亮。左右并排、自动换行对整个文件区生效（工具栏最右边的两个按钮），不用每个文件各选一遍；并排要差异够宽才可用。
- **已审阅**：读过的文件在差异标题行的右边勾上（文件树里也有勾），键盘 `V` 切换当前文件。勾上的文件收起来，工具栏上是进度和一键全部已审阅 / 清除。标记按文件的改动记：提交之后改动没变，标记跟得到「未推送」里；文件在审阅之后又改了，会标「有新改动」。只用来统计看过了哪些，不影响任何操作。
- **关联会话**：未归档的 DSH 会话可在宿主打开；由面板发起的代码审查会话带着「代码审查」标记。macOS 可按 ID 打开本机 Codex。ZCode Desktop 3.18.2 没有按本地任务 ID 打开原会话的桌面入口，按钮会复制标题并打开任务登记的 ZCode 工作区，仍需手动查找。
- 页签之间切换不重读，滚动位置、筛选、展开着哪些文件都还在。

**获取、拉取、推送**

- 获取：直接执行，只更新远端分支的本地记录，不动你的文件和分支；「落后」「未推送」的数字要获取之后才是准的。
- 拉取：先弹出计划（从哪个上游取回、把当前分支快进到远端、按本地记录落后几个提交），确认后执行 `git pull --ff-only`：能快进就快进，不能快进什么都不改。
- 推送：先弹出计划（把几个提交推到哪个远端的哪个分支，第一次推送时说明会在远端建立同名分支并设为上游），确认后执行普通推送：不强推，远端有本地没有的提交时会被拒绝；未提交的改动不会被推送。
- 没成功时，对话框里连同 Git 的原始输出一起留下。这三项会联网，并且照常运行仓库自己的钩子（比如推送前的检查）。

**AI 审查**

- 点「AI 审查」：在这个目录新开（或复用一个空白的）DSH 会话，发一份审查请求，然后切到这个会话。停在「未提交」上审的是未提交的改动，停在「未推送」上审的是还没推到远端的。请求只要两类结论：必须处理的问题，和建议。
- 发起后就能在清单里认出它：这棵工作树的行尾多一个四角星，「审查过」能把做过审查的工作树单独筛出来。
- 审完之后：详情的页签下面是一条结论；批注贴在差异里它说的那一行旁边——差异够宽时占代码右边一栏，窄的时候卡片排在这一行下面；「审查结果」页签按文件列出来。**复制结论**把还没审阅的文件里的结论复制成一段话（文件、行号、严重程度、结论），排好先必须处理后建议，可以直接贴给 AI 去改。
- 审过的改动已经不在了——审的是未提交的改动，现在都提交了；审的是未推送的改动，现在都推送了——这次审查的记录自动清掉。审查之后改动又变了、但审过的范围还在的，结论留着并提示位置可能不准；想看最新的点「重新审查」。
- 每个仓库可以换掉默认的「审什么、重点找什么」：右键菜单或结论条上的「审查提示词」。只替换基本那一段；范围、查看方法、只读约束和输出格式由面板固定给出。它存在这个仓库的 Git 公共目录里（`.git/worktree-desk/review-prompt.md`，所有工作树共用），不放进工作目录，所以不会出现在文件改动里，也不会被拿去审查。
- 这是让模型读你的改动：请求会发给 DSH 当前配置的模型，消耗它的额度；本仓库的审查提示词也在请求里一并发给模型。「只读」是请求里的要求，不是沙箱保证——会话用的是这个工作区默认的权限模式。

**本地分支**

- 工作树就是检出某个分支的目录，同一个分支同一时间只能检出到一个目录。只看一个仓库时，清单末尾的「本地分支」一段列出它的全部分支（默认收着，标题上写着几个检出了、几个没有）：检出了的分支后面是「查看工作树」，点它选中那棵树；其余标着「未检出」，没有目录，也就没有未提交的改动可看。**未检出不等于可以删除。**

**失效登记**

- 目录已经不存在的工作树登记折叠成一行，展开后可清理。清理先预览（`git worktree prune --dry-run`），确认后才执行；已锁定的登记不动，不删除任何文件。

**记住停在哪**

- 筛选、搜索词、选中的工作树、收起的仓库、停在的页签、滚动位置、文件树的形态、差异的显示方式，都记在本机浏览器里（localStorage）。切到别的面板再回来，或者重启 DSH 之后，接着上次的地方看。

## 怎么读这些数字

- 上游比较只针对本地已有的跟踪引用，面板自己不执行 `fetch`（点了「获取」才会更新）：「已同步」不代表刚刚检查过远端；「未设上游」不等于没有推送。
- 「起点」只陈述本地分支引用日志里实际记下的内容，不推测父分支；「上游」是当前分支配置的默认比较对象，两者可以不同。
- 工具、仓库旁的数字是匹配到的工作树数，包含主检出。这是目录关联，不是在线占用统计。

## 项目来源和目录匹配

默认从 DSH 工作区、Codex 桌面项目/聊天索引和 ZCode 本机项目/任务索引发现仓库。项目根本身不是 checkout 时，还查找它的直接子目录；不递归扫描整个 home 或磁盘。对同仓不同 checkout 按真实 Git common directory 去重，不按仓库名或远程地址合并。然后以 `git worktree list --porcelain -z` 为准，从仓库发现其它登记的工作树，包括临时目录和不同工具创建的目录。

没有被以上工具记录的仓库，可以在对应 DSH profile 的 `cordis.patch.yml` 中补充目录。多个条目使用同一个 `name` 即可组合成同一业务项目。这是可选的插件配置，不写入业务仓库。

```yaml
- id: worktree-desk
  config:
    projects:
      - name: 我的项目
        root: /absolute/path/to/frontend
      - name: 我的项目
        root: /absolute/path/to/backend
```

| 来源 | 关联依据 | 边界 |
|---|---|---|
| Codex | 本机 `state_*.sqlite` 的聊天 cwd；桌面项目索引可选 | 不把 `codex/` 分支名或目录名当作所有权，也不把更新时间当在线状态；子代理与守护审查线程不计入 |
| ZCode | 本机任务的工作树目录、执行目录，缺失时退回任务工作区 | 证据类型标在会话行；不把项目空间等同于实际占用 |
| DSH | 当前宿主会话摘要的工作目录投影，缺失时显示为初始目录关联 | 仅宿主报告运行且能定位工作目录时才标运行中 |

匹配取会话目录所在的最近 checkout，不把父项目下所有会话分配给每一棵树。只展示当前可关联的记录；历史记录、空白结果和索引不可用都不是工作树空闲的证明。SSH、容器及其它机器上的仓库不在范围内。

## 边界与降级

- 读取类接口（清单、仓库详情、单文件差异、清理预览、同步计划、审查结果、本仓库的审查提示词）是 DSH owner 认证的 GET 路由。插件只接受清单里的 ID，不接受任意路径、Git 参数或 URL。
- 会产生动作的接口都是独立的 POST 路由，并要求对应的 `X-Worktree-Action` 请求头：新开/打开会话、在系统应用中打开、清理失效登记、获取/拉取/推送。清理带上确认时看到的条数，同步带上确认时看到的计划指纹，对不上就拒绝。保存审查提示词也是这样一条 POST 路由（请求头 `X-Worktree-Action: prompt`）：只认清单里的仓库，正文最多 2 万字，写进这个仓库 Git 公共目录里的一个文件。
- 审查结果只从面板自己发起的那个会话里读，并且要求这个会话的工作目录就是这棵工作树；面板不读别的会话。
- 无插件数据库、遥测或聊天正文查询。Codex/ZCode 索引通过 SQLite 只读连接访问。
- 面板会把最近一次读到的结果留在本机浏览器的 localStorage（键 `worktree-desk.cache`）：仓库路径、分支名、工作树状态和匹配到的会话标题，和面板上显示的是同一批数据，只用于下次打开时先显示，不发往任何别处。界面偏好记在 `worktree-desk.prefs`；界面停在哪记在 `worktree-desk.view`；「已审阅」的标记记在 `worktree-desk.viewed`（只存文件路径的摘要和改动的指纹，不出现文件名）；哪个会话在审记在 `worktree-desk.reviews`。不希望留存的，清掉该站点的站点数据即可，面板回到默认状态。
- 读取用的 Git 用参数数组调用，关闭可选的索引刷新写入、hooks、fsmonitor 和全部传输协议。已跟踪文件依赖外部 clean/process 过滤器时跳过文件状态而不执行它，仍保留分支与目录信息。超时、过大的命令输出、丢失或不可读的目录都不会显示为「干净」。
- 获取/拉取/推送另用一套环境：只放开 https、ssh 和本地路径三种传输，照常运行仓库自己的钩子，不弹交互提示（没有凭据时直接失败并把 Git 的说明给你看），单次最多等 3 分钟。
- 单文件差异最多 1 MiB 或 4000 行，超出会截断并提示；未跟踪的新文件只读前 128 KiB 的原文，二进制和符号链接不读；文件清单最多列前 2000 项，超出的只计入总数并提示。

## 开发

```bash
npm ci
npm run build      # 打包 client/ → dist/client.js
npm test           # 纯函数与 Git 解析，含在临时仓库里真实执行清理、获取、拉取、推送
npm run dev:web    # 起一个隔离的 Web 宿主来手测（独立 profile，不挂桌面凭据）
npm run audit -- origin/main..HEAD   # 手动审查一段提交（见下面的「发布」）
```

`src/` 是宿主侧（来源适配、Git 读取、聚合与路由），`client/` 是独立侧栏面板，React 由 DSH 宿主提供。

前端重新构建后刷新页面就生效；`src/` 的改动要重启 DSH 才生效。两边版本不一致的那段时间（前端已是新版、宿主里的插件还是旧版），面板不显示宿主还做不到的操作，并在顶上提示重启一次——清单接口里带着宿主声明的能力列表，面板以它为准。

### 发布

代码只有一条主线：私有开发仓的 `main`。公开仓只收快照：一个版本一个提交，内容与主线同名标签的树逐字节一致，私有历史和本机文件不会过去。推送开发进度不等于发布。

```bash
npm run release -- --dry-run --bump patch   # 先演练：不提交、不推送
npm run release -- --bump patch             # patch | minor | major，也可 --version X.Y.Z
```

中间的 `--` 不能省：npm 会把 `--` 开头的参数当成它自己的配置，不加的话脚本收不到，演练就会变成真发布。脚本发现参数不完整会拒绝执行并提示写法。

一条命令依次完成：

1. 确认在 `main` 上、没有未提交的改动、不落后于远端。
2. 写版本号并提交、打标签。
3. 导出到干净目录，安装、测试、构建，并核对提交里的构建产物与源码一致。
4. 脱敏审查：发布提交的每个文件（内容和路径）加上发布说明。
5. 打包，核对包里只有清单内的内容。
6. 先推私有仓，再往公开仓推一个快照提交（推送时钩子再审一遍）。
7. 建 Release 并上传包和 `SHA256SUMS`。

- 中断后重跑同一条命令会接着做，不会重复升版本号或改写公开仓。
- `--notes <文件路径或文本>` 作为 Release 说明，默认只写版本号。
- **个人内容不进公开仓。** 写代码时就不把个人路径、真实账号、雇主和内部系统的名称、真实的聊天和任务内容写进去；测试样例和预览数据用虚构等价物（`/Users/x`、`me@example.com`）。
- 脱敏审查的规则是通用规则（`scripts/release-scan.mjs`：个人家目录路径、非示例邮箱、密钥样式、疑似凭据）加本机私有名单 `.local/release-deny.txt`（一行一个正则，`#` 开头是注释；这个目录已被忽略，只存在于本机）。有命中就阻止，审查本身出错也阻止，钩子找不到私有名单时同样不放行。自动扫描拦不住没有固定名单的内部标识（单号、内部仓库名、业务描述），发版前仍要看一眼改动里的样例和文档。
- 两道闸都调用 `scripts/release-audit.mjs`。发布脚本在推送前审查发布提交的全部文件和发布说明；推送到公开仓时，公开仓克隆里的 pre-push 钩子再审查快照提交本身（提交信息、作者身份、全部文件）和标签，手工 `git push` 也不例外。开发目录里指向公开仓地址的推送也会被它拦下来审，私有历史不能从这条路出去。钩子由发布脚本安装并保持最新；不要用 `--no-verify` 绕过钩子。
- 提交身份用 GitHub noreply 邮箱，在开发目录和公开仓克隆里各自设置。
- 建 Release 时，装了 `gh` 并且已登录就用 `gh`；否则用 git 自己的 GitHub 凭据调 API，凭据只留在进程内存里，不进命令行、不写文件、不打印。两条路都不行时，会列出要手动上传的文件。
